ARM 构建入口 `tools/hardware.sh build` 以 Foxy、Release、串行 executor 构建 `uav_px4_bridge` 依赖及独立 VINS `loop_fusion` 包。完整闭包实际完成15个包：`camera_models`、`px4_msgs`、`traj_utils`、`uav_interfaces`、`loop_fusion`、`plan_env`、`uav_navigation`、`uav_sim`、`vins`、`path_searching`、`uav_localization`、`uav_mapping`、`bspline_opt`、`ego_planner`、`uav_px4_bridge`。最终命令为：

```bash
cd ~/D435i-VINS-EGO-ROS2-hardware
bash tools/hardware.sh build
```

最终完整闭包日志总结为 `15 packages finished [4min 5s]`，退出码为0。较早完整 ARM 首次编译日志另记录了VINS/EGO对象文件实际生成；此后只针对修复包增量重建。每次修复仅重建受影响包，再续跑闭包。

干净 shell 使用 `source tools/hardware-env.bash` 后执行冒烟，以下9个导入均通过：`rclpy`、`uav_sim.geometry`、`uav_localization.node`、`uav_mapping.node`、`uav_navigation.node`、`uav_px4_bridge.px4_bridge_node`、`uav_px4_bridge.vio_ego_bringup`、`uav_interfaces.action`、`px4_msgs.msg`。`NavigateToPose`、`VehicleOdometry` 类型加载通过；`python3 tools/generate_vins_config.py --help` 返回帮助并以0退出。ROS 包入口可见 `loop_fusion_node`、`px4_bridge`、导航监督/可视化、建图输入和深度健康工具。

对 `vins_node`、`loop_fusion_node`、`traj_server`、`ego_planner_node` 运行 `ldd`，四项均无 `not found`；VINS和回环二进制解析到固定 OpenCV 4.2 / Ceres 2.1 路径。

## Foxy 兼容修复

- ARM 构建环境下条件排除 Gazebo-only `ros_gz_bridge` 运行依赖，仿真配置的默认依赖保留。
- 自维护 Python 节点适配 Foxy executor、Future、信号处理和 RCLError API；PX4 桥接的 Python 3.8 类型注解启用延迟求值。
- VINS 与 loop_fusion 共用的 cv_bridge 头文件增加 `.hpp` 优先、`.h` fallback；EGO `plan_env` 同样保留双发行版兼容。
- `traj_utils` 的 ROSIDL 消息依赖仅保留消息字段实际使用的 `std_msgs`、`geometry_msgs`、`builtin_interfaces`；`rclcpp` 仍保留为普通 C++ 依赖。该修复消除了 Foxy 缺失的 `libstatistics_collector__python.so` 生成依赖。
- Foxy 的 `rclcpp` 订阅回调改用支持的按值 `ConstSharedPtr`；消息过滤器回调保持原状。`traj_utils` 头文件安装目的地改正为下游 `<traj_utils/...>` 期望路径。
- 第三方补丁登记在 `dependencies/sources.json`：VINS `0023`，EGO `0062–0065`；补丁SHA与被修改上游文件SHA已核对，VINS/EGO补丁做了反向/正向应用往返。
