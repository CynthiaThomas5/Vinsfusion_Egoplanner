# GOAL C EGO Fast DDS ACKNACK / DATA 重传对齐 #378–#379

- **问题**：#372–#377 已看到 loopback 上有首份 DATA，但部分序号没有对应 EGO receive API 返回记录。需确认可靠性控制流是否请求缺失序号、重传是否能与 EGO 收包及 DataReader history 按同一序号关联。
- **方法**：在 planner-only 隔离仿真 #378/#379 中仅捕获匹配 writer/reader 的 RTPS DATA、ACKNACK、HEARTBEAT、GAP 元数据。未保存 PCAP 或 RTPS/应用载荷。#378 记录 ACKNACK 位图但未保存 submessage flags；#379 加入 rtps.sm.flags，并生成可重复的 [ACKNACK gap correlation](../../artifacts/runs/p2-ego-fastdds-acknack-bitmap-flags-diagnostic-20261021-379/acknack-gap-correlation.json)。run-local EGO overlay 复用 #377，canonical 源码、QoS、socket 缓冲与 freshness gate 均未改。
- **结果**：
  - #379 的2.316622 s successful-take gap中，sequence615的首份 DATA 到达 EGO participant UDP port 前0.122 ms，但未由 EGO receive API返回。EGO reader发送ACKNACK（count38，bitmap base615，numBits=1，bitmap 00000080，flag 0x01 little-endian）请求615。5.119933 ms后，mapping writer向精确EGO reader重发615；约10.129 μs后EGO receive API返回。随后Fast DDS reader listener单次报告[615,662]，48条DataReader history更新全部成功；下一次successful take结束该gap。
  - #378 的2.478834 s gap里，ACKNACK count23、base374、numBits29、bitmap 48010080。用#379同环境直接记录的little-endian flag解码，位图请求374/397/399/402。对应精确reader DATA重传发生在ACKNACK约5.116–5.196 ms后；EGO API在gap内返回374和397，399和402的API回执分别晚于下一次successful take约4.5和42.6 μs。gap内history只到398，未含399/402。该 run 的flag未保存，位图字节序解释明确标为跨run推断；详细边界见[跨run解码报告](../../artifacts/runs/p2-ego-fastdds-acknack-recovery-diagnostic-20261021-378/acknack-cross-run-decoding.json)。
- **结论**：这两轮直接把ACKNACK请求、同序DATA重发、EGO receive API和Fast DDS history/listener按序关联起来。Reliable RTPS recovery与序号有序交付是观察到的停顿机制。仍未确认首份DATA没有进入EGO receive API的内核/传输原因。SO_RXQ_OVFL式socket drop计数与接收队列为participant socket聚合数据，不能逐序号归因；#378 gap bracket drop +109（前/后等长窗+0/+35），#379 +33（+79/+51），只提供压力背景，不能作为特定包丢弃证明。
- **边界与安全**：两轮均planner-only，没有goal、PX4、trajectory server、truth/control订阅或控制发布；capture只输出元数据，不保留PCAP/载荷。没有地图、路径净空、轨迹执行、SITL飞行或实机验收证据。Fast DDS StatefulReader::NotifyChanges 源码按writer序号依次推进通知逻辑：[2.14.6源码](https://github.com/eProsima/Fast-DDS/blob/v2.14.6/src/cpp/rtps/reader/StatefulReader.cpp#L1107-L1164)；ACKNACK与SequenceNumberSet位图语义依据 [OMG DDSI-RTPS 2.0](https://www.omg.org/spec/DDSI-RTPS/2.0/PDF)。
