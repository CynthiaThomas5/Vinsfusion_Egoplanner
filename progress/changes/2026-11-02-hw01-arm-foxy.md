# HW01 ARM/Foxy 构建与部署基础

对话摘要：[HW01 实施](../../collaboration/dialogues/2026-11-02-hw01-execution.md)。模块要求和边界见[硬件任务书](../../docs/hardware-agent-workbook.md#4-hw01-armfoxy构建与部署基础)。验收结果：[HW01证据](../evidence/hw01-arm-foxy-20261102.md)。

## 修改

- 新增 `tools/hardware.sh build`：固定依赖前缀、Release、串行构建当前 VINS（含 `loop_fusion`）、EGO 和 `uav_px4_bridge` 依赖闭包；新增 `tools/hardware-env.bash` 用于干净shell加载。
- `uav_sim` 与 `uav_px4_bridge` 在 ARM 构建环境条件排除 Gazebo-only `ros_gz_bridge` 运行依赖，仿真默认依赖保持。
- 自维护 Python 节点适配 Foxy API/Python 3.8；PX4桥接的 `trajectory.py` 与 `vision_odometry.py` 延迟注解求值，修复 `tuple[...]` 导入异常。
- VINS、loop_fusion 和 EGO 的 cv_bridge 头文件添加 Foxy `.h` fallback；EGO直接订阅回调适配 Foxy；修复 `traj_utils` 消息生成依赖与公共头文件安装路径。
- 所有第三方修复登记到 `dependencies/patches` 与 `dependencies/sources.json`，包含基准顺序、补丁哈希和修改文件哈希。

## 验证

- Jetson Nano ARM64/Foxy：`bash tools/hardware.sh build`，15包目标闭包通过；逐个只重建失败/受影响包后续跑闭包。
- 干净 shell 导入9个核心模块与ROS接口类型通过；VINS配置生成器 `--help` 和ROS入口清单通过。
- 对VINS、loop_fusion、traj_server、ego_planner四个二进制执行 `ldd`，无未解析库；VINS/loop_fusion解析到Ceres 2.1与OpenCV 4.2。
- 来源补丁SHA校验及VINS/EGO补丁反向/正向应用往返通过；最终原始日志路径与SHA见证据报告。

构建有上游VLA/旧ConstPtr/未使用参数等警告，但无阻断错误。未启动传感器、PX4、SITL或飞行，所以结果不构成硬件运行或飞行资格。下一模块HW02。
