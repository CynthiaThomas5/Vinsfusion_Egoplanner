# P2 EGO 里程计接线与 QoS

- 关联对话：[任务摘要](../../collaboration/dialogues/2026-10-16-023-p2-ego-odom-qos.md)。
- 文件与行为：定位适配器的 `/localization/optimized_imu_odom` 改用 reliable QoS，`/localization/imu_odom` 维持 sensor-data best-effort；EGO 来源新增 patch 0006，为规划器两个里程计消费者配置完整话题名。同步更新接口说明、EGO patch 清单和依赖锁状态。
- 验证：Jazzy 新 overlay 中 `uav_localization` 构建通过；动态 run #03（ROS_DOMAIN_ID 119、隔离 Gazebo partition）运行 40.031 秒。定位 TRACKING、376 个优化位姿、169 组建图配对；QoS 图中定位发布端 reliable、EGO 两个订阅 reliable、建图订阅 best-effort，未出现 reliability 不兼容告警。EGO 从 INIT 进入 WAIT_TARGET／SEQUENTIAL_START，后续记录一次计划成功与多次轨迹生成失败。额外运行 #08 用于停机诊断，定位 QoS 仍无冲突，EGO 收到 SIGINT／SIGTERM 后仍在运行，最终对该测试 PID 使用 SIGKILL。证据与日志哈希见 [EGO 里程计 QoS 报告](../evidence/p2-ego-odom-qos.json)。
- 局限：EGO 默认 sequential-start 下轨迹尝试多数失败；仅一次成功不能证明稳定规划。EGO 停机与 stale 故障响应未验证，#08 不能干净停止，需调查退出路径。本次没有 PX4、控制器或控制发布者。
- 下一步：检查 sequential-start 的失败原因和 EGO signal/shutdown 行为，设计有明确触发和重复标准的只读规划场景；随后做受控 depth-stale、epoch reset 和时钟回退验证。
