# P1 单 D435i 模型与实际静态校准

对应[对话摘要](../../collaboration/dialogues/2026-10-16-004-p1-sensors.md)。

## 修改

- simulation/models/d435i：一个刚体上的双目、对齐深度、RGB、相机 IMU；模型尺寸、基线、视场、分辨率与源 frame。
- simulation/worlds/sensor_calibration.sdf：固定支架、3 m 校准平面与视觉标记；不是在线占据地图。
- config/components/simulation/d435i_bridge.yaml：仅 GZ→ROS 传感器与 clock 桥。
- src/own/uav_sim：实际可构建的 Python ROS 包、从 SDF 生成内参与 URDF、Gazebo／桥／TF 启动与退出联动。
- tools/check_sensors.py：只读 ROS 校准探针，检查编码、内参、光学 frame、深度单位、IMU、时钟、TF 平移、双目配对与几何视差，报告实际接收频率。
- tools/test_sim_geometry.py：离线检查基线、optical 轴向及旋转安装拒绝。

## 验证

- colcon 实际构建 uav_sim：通过，日志在 artifacts/runs/p1-sensors-20261016。
- python3 tools/test_sim_geometry.py：2 项通过。
- 真实 Gazebo Harmonic 8.14 + Jazzy 单向桥运行，最终只读探针全部通过，见 [证据](../evidence/p1-static-sensors.json)。
- 首轮探针未通过内参检查：生成器使用了 width/2−0.5，而 Gazebo 使用 width/2，已修正；深度 CameraInfo 默认源话题也已正确映射。保留初始失败报告。
- 探针首次还遇到 numpy bool JSON 序列化异常，已将检查结果转为 Python bool，并完成两次实际复测。
- 目标 launch 收到 SIGINT 后，Gazebo、桥及 robot_state_publisher 均正常退出；没有全局清理其他项目进程。

## 局限与下一步

当前模型理想、无噪声／畸变／红外投射／真实深度缺测；无机体安装与动态验证。软件渲染的深度实际接收频率约 12 Hz、RGB 约 25 Hz，不按配置 30 Hz 宣称全链路达到 30 Hz。下一步完成动态运动与同步／几何检查、由同一 SDF 生成 VINS 配置并开展无真值初始化；P0 的其余依赖冻结仍未完成。P1 不标记 passed。
