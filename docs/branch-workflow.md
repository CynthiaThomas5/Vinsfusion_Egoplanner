## 日常探索

```bash
cd /home/work/D435i-groundstation/explore
git status --short --branch
# 在此修改、运行对应测试，再按具体文件暂存并提交。
git push
```

无需在演示目录反复切分支。两个目录同时存在；探索目录的源文件修改不会改变演示目录的源文件。不要在探索目录运行桌面启动器安装脚本，否则它会把全局入口改指向探索版本。

探索目录是新工作树：Git 不会自动复制忽略的第三方源码、build/install 或运行数据。本机已从稳定目录复制 `src/vendor/` 为独立文件，用于保留当前本地依赖和通过文档结构检查；这些副本仍被忽略，不随分支推送，也不等于已完成锁定依赖重建或构建验证。`external/`、build/install 和运行数据未复制。异机按锁定依赖获取；探索使用自己的构建，不把 build/install 链接到稳定目录，不复制私人凭据到仓库。

外层本地 `AGENTS.md` 指示以后默认进入探索目录；探索分支 AGENTS 也记录边界。该本地导航文件不属于 Git 提交，异机克隆后应按此文档选择目录。

## 运行环境隔离是第二层

当前两份代码仍使用同一组 Nano 配置、Docker 镜像、`d435i-gs-*` 容器名以及用户状态目录。**Git 分支和 worktree 不会隔离这些资源。** 当前入口尚不支持两套完全独立的并行设备会话，不要同时运行两套。

本轮未连接或改动 Nano，未启动/停止实验，未替换镜像、安装和桌面入口。后续每个探索任务按实际影响准备隔离：

- 只改源码/离线分析：在探索目录实施和验证，不部署至稳定环境。
- 修改 Nano 算法/依赖：先建立独立 Nano 源码目录及独立构建安装前缀，保留稳定源码、安装和配置；确认硬件脚本的安装清单、会话身份与路径检查均适配后再部署。
- 修改地面站显示/容器：先保留当前镜像的实际 ID 与可恢复归档，构建时用独立探索镜像标签；若要并行，必须进一步改造容器名、状态目录和域配置，不能只换源码路径。
- 修改设备标定、服务、系统库、固件或 PX4 参数：先保存可核对的实际版本/配置及恢复步骤。Git bundle 只备份受跟踪源码，不备份这些环境，也不备份忽略的实验数据。

需要演示时，结束探索所属会话，确认设备/运行环境回到记录的稳定版本，再使用原 `project/` 入口。运行状态不明时遵守既有停止流程，不强杀控制链。

## 探索成果如何进入稳定版

探索提交不会自动进入 main。一次只选择一个有明确验证证据的改动，完成受影响测试、目标机验证和实际演示回归，并取得用户的稳定版更新授权，再晋级。

优先在临时集成分支挑选已验证提交，避免把未完成探索一起合入。验证后才更新 main，并建立新的日期版本标签；保留旧标签和原恢复资料。无论分支是否相同，运行资格始终以对应证据为准。

## 从源码基线恢复

稳定目录保持未改时，直接使用原入口，不需要 reset。如果只是探索分支改坏，保留故障现场，另建恢复工作树即可：

```bash
git -C /home/work/D435i-groundstation/project worktree add --detach \
  /home/work/D435i-groundstation/recovery-demo demo-baseline-2026-11-09
```

若本地 Git 元数据损坏，可从远程标签或离线备份重建新的源码目录：

```bash
git clone --branch main \
  /home/work/D435i-groundstation/backups/demo-baseline-2026-11-09.bundle \
  /home/work/D435i-groundstation/recovery-source
git -C /home/work/D435i-groundstation/recovery-source switch --detach demo-baseline-2026-11-09
```

上述恢复只重建源码。按固定依赖准备运行环境，核对安装/镜像身份后再使用；不以强制重置、删除工作目录或改动既有演示路径作为默认恢复方式。
