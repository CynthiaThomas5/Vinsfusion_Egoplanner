# D435i 项目使用指南

适用版本：`gs02-20261106-freeze01`，编写日期：2026-11-07。

本指南以当前 Debian 地面站和 Jetson Nano 已部署环境为基础。日常建议先使用“VINS 实时显示实验”。真实机体的 HW08/HW10 尚未完整验收；本文的硬件操作限于感知、建图和规划计算。仿真入口单列在文末。

## 1. 设备与目录

| 设备 | 职责 | 项目位置 |
| --- | --- | --- |
| Debian 地面站 | 操作入口、RViz、记录、QGroundControl | `/home/work/D435i-groundstation/project` |
| Jetson Nano | D435i、VINS、建图、EGO 和导航计算 | `/home/jetson/D435i-VINS-EGO-ROS2-hardware` |

以下命令除明确标注外，都在 **Debian 地面站终端**执行。地面站需要已登录图形桌面，Nano 需要供电正常，D435i 接在 Nano 上，两机网络互通。

地面站配置文件为 `config/groundstation/debian.env`：当前 Nano SSH 别名 `uav-nano`，镜像 `uav-groundstation:jazzy-20261104`，本地显示域 83、Nano 域 0。Nano 地址变化时检查地面站 `~/.ssh/config` 的别名配置。不要把密码或私钥写入项目。

## 2. 最快启动：VINS 实时显示与绕圈记录

### 第一步：进入目录并检查环境

```bash
cd /home/work/D435i-groundstation/project
uav-groundstation check
uav-groundstation status
```

`check` 应能输出镜像身份、Nano 主机信息和 `Groundstation imports PASS`。没有统一会话时，Nano 返回 `No unified hardware session.` 是正常状态。

如果提示找不到 `uav-groundstation`，可直接调用仓库脚本，所有子命令相同：

```bash
bash tools/groundstation.sh check
bash tools/groundstation.sh status
```

若已有会话或 viewer，先确认它属于哪个实验。已有纯感知绕圈实验使用 `experiment-stop` 收尾，已有普通纯计算会话按第 5 节停止，再启动新实验。

### 第二步：启动完整显示实验

```bash
uav-groundstation experiment-start
```

也可点击桌面“启动VINS绕圈实验”入口。脚本会先启动地面站 RViz、显示 relay 和记录器，再启动 Nano 新的感知会话。启动过程需要等待，成功提示类似：

```text
VINS定位有效，静止起点已记录。可以开始慢速绕圈；运行ID：hw10-groundstation-...
```

等待期间先保持相机静止；看到上述提示、确认画面正常后再慢速移动。脚本会收集 20 个基线位姿，但不会独立判断相机是否真正静止，因此起点静止需要操作者保证。

### 第三步：查看与移动

RViz 应显示左右目特征图、稀疏点、相机视锥、机体轴和轨迹。默认 MoveCamera 工具支持左键旋转、中键平移、滚轮缩放。

在空间允许的范围内缓慢绕圈并返回起点，尽量恢复初始朝向，然后保持静止。观察定位是否有效、轨迹是否更新、双目画面是否停顿。新终端可查询：

```bash
uav-groundstation status
uav-groundstation local-ros topic echo /hardware_view/status --once
```

进程 alive 不等于定位有效。若显示 INVALID、LOCKED、stale 或明显卡顿，暂停移动，记下大致时间并保留日志；不要反复叠加启动。

### 第四步：正常停止并保存

返回起点并静止后，在地面站执行：

```bash
uav-groundstation experiment-stop
uav-groundstation status
```

该命令先停止 Nano 的 perception 会话，再停止显示容器和记录器、保存终点与 console 日志。成功收尾后应没有统一硬件会话，也没有 `d435i-gs-view` 容器。

绕圈数据是 VINS 自身估计，首尾距离不能当作独立测量的绝对定位误差。

## 3. 记录保存在哪里

启动时记下终端打印的 `<run_id>`。地面站记录位于：

```text
/home/work/D435i-groundstation/project/artifacts/runs/<run_id>/
├── viewer-status-samples.jsonl
├── visual-receive-events.jsonl
└── groundstation/
    ├── circle-ready.json
    ├── circle-start.json
    ├── circle-poses.jsonl
    ├── circle-end.json
    ├── recorder-summary.json
    └── viewer-console.log
```

`circle-poses.jsonl` 保存逐姿态记录；start/end 文件保存首尾信息；summary 保存记录统计；两个 viewer 文件用于接收时延、更新间隔及资源诊断。`viewer-console.log` 由正常 `experiment-stop` 在能取得 Nano run_id 时保存。

Nano 原始日志另存于 Nano 项目的 `artifacts/runs/<run_id>/`，不会自动等同于地面站目录。若启动中途失败，部分文件可能尚未生成。

## 4. 其他启动方式

这些方式与完整绕圈实验互斥使用，先结束已有会话。`view` 和 `map-view` 在前台运行，建议各用一个终端。

### 只启动感知，查看简洁轨迹

```bash
uav-groundstation nano-start perception
uav-groundstation view
```

`view` 默认读取已有定位日志，不添加完整双目和特征显示。需要完整双目显示与绕圈记录时，使用第 2 节的 `experiment-start`，由它安排 relay 先于 VINS 启动。

### 启动建图

```bash
uav-groundstation nano-start map
uav-groundstation map-view
```

map 层启动传感器、定位及地图，不启动导航规划链。等待定位与深度融合后再观察占据数据。

### 启动建图与规划计算

```bash
uav-groundstation nano-start plan
```

另开终端查看：

```bash
uav-groundstation map-view
```

plan 层运行感知、建图、EGO、traj_server 和导航 action；不会自动发送目标，也不启动 PX4 bridge。地图窗口蓝色表示 occupied、橙色表示膨胀占据、粉色表示最近参考采样记录；粉色线不是完整未来 B 样条的安全证明。

以下命令查询 Nano 原生 ROS 接口：

```bash
uav-groundstation ros topic list
uav-groundstation ros action list
uav-groundstation ros interface show uav_interfaces/action/NavigateToPose
uav-groundstation ros topic echo /localization/status --once --qos-durability transient_local
```

导航接口为 `/navigation/navigate_to_pose`。目标需要当前 `odom_<epoch>`、完整三维位置和 yaw；地面 compute_only 模式用于规划计算，不会驱动真实飞机到达。目标构造与接口约定见 [接口契约](contracts.md) 和 [导航模块说明](../src/own/uav_navigation/README.md)。

### QGroundControl

```bash
uav-groundstation qgc
```

打开 QGC 不代表已经连接飞控。当前没有配置与 Nano DDS 常驻链路并行的双向 MAVLink 物理链路。

`uav-groundstation telemetry` 是条件性只收遥测入口：需要 Nano `/dev/ttyACM0` 存在、空闲且处于 MAVLink 模式；不会转发 QGC 的命令和参数请求。不要为打开遥测而停止现有 Agent 或抢占它的串口。

## 5. 普通感知／建图／规划会话如何停止

对于第 4 节启动的普通纯计算会话：

```bash
uav-groundstation stop-view
uav-groundstation nano-stop
uav-groundstation status
```

`stop-view` 只关闭地面站定位和地图显示，Nano 计算会继续。`nano-stop` 停止 Nano 所属纯计算会话，并恢复脚本保存的接收缓冲区设置。完整绕圈实验请优先使用 `experiment-stop`，以保留其日志收尾流程。

Micro XRCE-DDS Agent 是独立通信服务，正常结束上述实验后可能仍为 active；这不等于 VINS 会话没有停止。

如果 status 显示真实 ev/control 层，普通 stop 会拒绝处理；需按已有流程确认飞控落地上锁并结束控制链。本文不提供真实武装或起飞步骤。

## 6. 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| SSH 连接失败 | 执行 `ssh uav-nano hostname`，检查 Nano 供电、网络和 SSH 别名 |
| Docker 不可访问／镜像不存在 | 用 `docker info` 与 `docker image inspect uav-groundstation:jazzy-20261104` 检查部署环境 |
| `Log in to the graphical desktop first.` | 登录 Debian 图形桌面后重新执行，检查桌面 DISPLAY/XAUTHORITY；不要随意放开 X11 权限 |
| 已存在会话或 relay | 先 `status` 确认归属，再使用对应停止命令，不删除状态文件强行启动 |
| baseline 未就绪／启动超时 | Nano perception 可能已经启动；先检查 status 和日志，勿再次直接 start |
| INVALID／LOCKED | 查看定位失效原因，保存本次日志；按流程停止后排查，不绕过健康检查 |
| 双目或轨迹卡住 | 暂停移动、记录发生时间，保留 run_id 和 viewer 日志；历史长滞后根因仍未定位 |
| 地图空白 | 确认启动的是 map 或 plan，定位有效且深度正在融合；纯 perception 没有占据地图 |
| 停止命令失败 | 保留终端报错及会话状态，核对所属进程；不要清空 `.runtime` 或强杀所有 ROS 进程 |

## 7. 仿真启动（独立环境）

以下命令用于 Gazebo/PX4 SITL，需另备项目固定仿真镜像、依赖和构建产物，以及 NVIDIA 图形环境。当前 Debian 地面站显示镜像不包含完整仿真环境，不能据此假定本机直接可运行。

在已配置的仿真工作站项目根目录执行：

```bash
./start.sh start pillars  # 打开柱群 Gazebo + RViz，不起飞
./start.sh status         # 查看仿真状态
./start.sh fly pillars    # 仿真前检、任务、自动降落上锁
./start.sh status         # 查看任务与独立评估结果
./start.sh stop           # 确认任务结束、落地上锁后停止
```

可选场景：`room`、`floorplan2`、`pillars`。`fly` 会实际执行仿真任务，运行时保持终端打开；评估查看对应 run 的 `qualification.json`。仿真环境准备见 [运行与构建](running.md)。
