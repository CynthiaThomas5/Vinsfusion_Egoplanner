# 单 D435i 视觉导航 Goal：稳定基线、规划安全与可重复交付

原目标设立：2026-10-16。替代版本：2026-10-21 / v2。状态：实施中，未完成最终验收。

本文件替代此前 Goal 的实施安排，是当前目标与完成契约；保留单 D435i、无 GPS／真值位置辅助、唯一控制出口和 A–H 最终要求。当前状态只在 [progress/CURRENT.md](progress/CURRENT.md) 维护，阶段和执行步骤见 [milestones.json](progress/milestones.json)，最终条款见 [goal-checklist.json](progress/goal-checklist.json)。本文制定计划，不构成任何运行步骤通过证据。

## 要交付的结果

在本仓库交付一套可从固定依赖重建、按文档启动并重复验收的 ROS 2 Jazzy／Gazebo／PX4 仿真系统：

**单 D435i 双目＋相机 IMU → VINS → 采样时刻位姿配合深度在线建图 → EGO 安全轨迹 → 唯一 PX4 Offboard 控制桥 → 起飞、指定三维位置与 yaw、绕障、到达、降落并解除武装。**

VINS 同时支撑地图、规划和 PX4 EKF2 外部视觉融合。以同一套固定源码、参数和启动方式同时证明定位、输入连续性、机体净空及任务完成；不同实验版本的最好结果不能拼接成最终成功。

## 范围与实施边界

- 主项目为本仓库。继续工作先执行 `git status --short --branch` 并读取 README、AGENTS、GOAL、CURRENT 和里程碑；保护既有未提交修改。
- 只做单 D435i、静态障碍、低速室内、人工指定三维目标。保留导航、地图、RGB-D、定位状态与 epoch 接口；信念、语义和自主探索算法不在本轮范围。仿真结论不外推真实设备。
- 不使用激光定位、GPS、Gazebo 真值位置或完整世界地图辅助最终在线链路；不靠真值初始化或隐式定位回退。只读评估真值须隔离，不能向导航或控制反馈。
- `uav_px4_bridge` 独占 PX4 控制设定点、OffboardControlMode 和模式协调；定位适配、评估和实验观察器不得新增控制出口。
- 自维护源码在 `src/own`；第三方在 `src/vendor`，只保留一份算法。第三方修复在 `dependencies/patches` 记录基准、顺序、哈希与许可。旧部署工程和 ROS_SEARCH 实验区只读。
- 配置在 `config`，模型在 `simulation`；外参、PX4 参数和地图设置保留单一来源。允许按证据实现源码、配置、容器、测试与 SITL 修复；不启动真机飞行、不修改真实设备配置，不擅自提交或推送。
- 不以放宽健康门、重复旧消息、重写源戳、清除未观测区域或自动恢复旧会话使实验表面通过。调整阈值须先有独立校准理由、版本记录和重跑要求。
- 常规实施选择自主推进；真正权限或外部条件受阻时准确记录。除非新的失败证据要求替换，优先修复现有链路，避免同时更换 VINS、EGO、地图和控制架构。

## 当前执行顺序与退出标准

S1–S6 是对剩余 P4–P6 工作的排序，不重命名或重置 P0–P6。步骤未通过可以开展后续只读分析、离线检查及不执行候选轨迹的实验，但不得把尚未通过安全条件的轨迹接入飞行。每次改动先定义预期行为与验证方法；失败、中断和排除的运行都保留。

### S1 固定 GPU 运行环境与纯视觉飞行基线

- 将已验证的 GPU 容器、渲染方式、启动与停止流程收敛到仓库入口；实际检查渲染后端，记录镜像、源码、依赖、配置哈希与有效启动参数。GPU 未生效时明确阻止依赖该环境的飞行，不能静默退回未验证的 CPU 路径。
- 优先保留当前默认 3 秒低频遥测接收龄门和其他健康限值；不把此前 4 秒隔离覆盖当作修复。记录源时间、monotonic 回执、RTF 和时钟映射状态，区分仿真慢、发布周期与交付延迟。时钟拟合失败不得回退成旧控制时间戳。
- 在完整 VINS／地图／EGO 进程负载下先关闭导航目标，验证冷启动、初始化、EKF2 实际融合、解锁、起飞、悬停、降落和解除武装。hold 参考的固定方式先记录和对照，再按证据修复，不能悄悄改变基线。
- **出口**：同一固定版本连续 3 次独立冷启动，每次空中无目标保持至少 30 仿真秒，记录对应墙钟时间；无定位健康锁定、时间映射失败或控制信号丢失，最终 landed/disarmed。保留只读误差评估，给出定位及保持误差，不能只看状态 TRACKING；证明无 GPS／真值辅助、唯一控制发布者。失败后修复再重新开始连续重复。
- 此为诊断基线，不替代 F 冻结后的正式 D／E 验收；GPU 结果不声明 CPU 或其他机器已获验证。

### S2 查清并修复 hold 到 EGO 轨迹的切换

- 固定 S1 环境、场景、限值和观察负载，对照：固定参考悬停、EGO 计算但桥保持原参考、桥实际执行 EGO。诊断控制仍全部经唯一 bridge；不执行组必须明确阻止候选轨迹进入控制。
- 对齐目标派发、B-spline、PositionCommand、PX4 设定点、估计位姿／姿态和首个 VINS 质量越线时刻；复用现有分组代价观测，必要时采集对应特征／图像，区分视觉、IMU、边缘化代价和运行时负载。
- 审查进入 hold 时参考是否固定、首次轨迹与重规划起点的位置／速度／航向连续性、轨迹有效时间和传感器到机体的转换。参考不连续或过期时拒绝并说明；需要过渡段时也须经过碰撞检查。不能在 bridge 临时生成未经检查的绕行或平滑路径。
- 当前位置按轨迹当前时刻采样；`time_forward` 是默认 yaw 前视，不能当作位置提前执行的根因。位置跟踪及速度／加速度前馈须分别验证，不同时改变多项控制行为。
- 不先提高质量门或增加越线等待来换成功。特征筛选等候选只有在受控干预改善独立误差与任务结果后才能纳入默认版本。
- **出口**：形成可复现故障机制、针对性修复和回归报告；统一版本下至少 3 次独立冷启动重复目标运行，参考连续、定位与时序健康、动作及降落成功。零位移目标仅验证切换，不作为实际位移或避障证据。涉及位移的实验先满足 S4 对该轨迹的安全条件。

### S3 让 EGO 获得连续、新鲜、身份一致的地图输入

- 在固定 GPU 基线复测已有接收空窗。有限成对比较两端 QoS／传输策略，记录实际融合源戳、最长融合间隔、丢弃配对数、队列和资源曲线；不继续仅凭增大 history／buffer 宣称修复。
- 保留深度采样时刻的插值位姿、时间跨度上限、原始 stamp、epoch／map_id 与 reset 确认；不外推、不拿最新位姿替代、不放宽现有 freshness 门来隐藏丢帧。
- 明确区分 adapter 已转发、EGO 已收到配对、EGO 实际融合和地图可用于目标四种事实；地图 ready 与接受目标必须依据实际融合新鲜度，而非上游 ready 或缓存点云单独判定。
- 若有限 QoS 对照无效，再评估单一深度＋配对位姿接口，继续使用现有唯一 `plan_env` 地图。并发调整前先审查共享状态；不直接以多线程掩盖停顿。
- **出口**：固定完整负载下至少 3 次独立新 epoch 运行，每次目标前到任务结束的实际融合间隔／源龄满足当次固定门限，无正常输入下的长空窗与无界积压；断流时门按规定关闭，恢复／reset 身份正确。该诊断结果不替代正式 10 分钟测试。

### S4 统一未知空间、地图边界与完整机体安全规则

- 将 A*、优化器、最终全活动曲线检查的 occupied／free／unknown／inflated／地图外含义统一；缺少可用地图或进入未验证空间时拒绝。安全规则覆盖整条待执行轨迹与重规划，不只检查控制点、中心线或前 2/3。
- 基于实际机体和相机碰撞几何明确自身过滤／起点处理；不得用任意半径起点豁免把机体外未知区域当 free。相机固定安装，观察动作须由真实仿真机体完成，不能以独立转动相机的实验替代。
- 根据地面、坐标原点、起飞状态和机体包络确定地图范围。扩大地图下界不会自动形成 free；起飞与落地阶段也须有明确地面接触及自身区域规则。
- 根据机体尺寸、地图／定位／跟踪误差、总延迟和实测制动能力建立安全预算，避免重复计入或遗漏；0.099 m 默认膨胀和 0.5 m 实验值均不直接视为已验证净空。
- 分批审查、回归并纳入有效补丁：失败停止、重试冷却、统一碰撞查询、完整曲线检查。密集检查需覆盖采样间隙并验证运行开销；高频诊断默认关闭。合并后从锁定源码干净重建，隔离 overlay 的旧结果不能代替默认集成验证。
- **出口**：在至少两种障碍布局和独立 epoch 中取得与候选轨迹匹配的地图快照，回读后保守检查完整机体连续扫掠；规则允许的起降／自身接触范围之外，无 unknown、越界或禁止区域侵入，净空满足预先声明的诊断预算。机体接触与实际跟踪净空仍由后续飞行评估，不将离线通过当作飞行通过。

### S5 收敛统一版本，冻结标准并完成有位移的导航

- S1–S4 通过后收敛到同一套默认源码、参数和启动方式；简单航点和 EGO 模式共用控制出口。先诊断短距离位移、yaw、高度变化与取消／替换／不可达反馈；位移须明显大于到达容差，不能以零位移或原地容差命中代表运动完成。
- 依据独立校准、观测范围与机体安全预算完成下方 F 的单一验收配置。冻结前的运行明确标记诊断；冻结后才开始 D／E 正式运行。
- **出口**：固定版本下有位移三维目标与 yaw 可重复完成，并形成预先冻结、带理由／测量方法／哈希的验收标准；传感器、VINS、地图、EGO、EKF2 和唯一控制桥的运行身份一致。更改影响结果的实现或阈值后重跑相关回归与正式测试。

### S6 正式验收与用户交付

- 按 A–H 完成四类正常场景各 3 次独立冷启动、不可达目标、六类故障各至少 2 次独立注入，以及至少一次连续 10 分钟完整负载任务。
- 实际记录机体碰撞／间距、定位与跟踪误差、到达／yaw、重规划、资源与端到端延迟；故障降落量化漂移与最终 PX4 状态。发出 Land、action success、有轨迹线都不能代替结果。
- **出口**：A–H 与 P0–P6 均有有效证据，S1–S6 全部关闭，最终固定版本干净重建并能按交付文档重启示例。全部失败／中断的正式 run 同样列入最终报告。

## 最终回收标准

### A 可重建与可启动

1. 依赖精确到 commit 或不可变镜像版本，补丁应用顺序明确，源码与参数可追溯；来源下载不依赖临时目录里的唯一副本。
2. 使用新的 build／install 目录或干净容器，按 README 完成一次真实重建，覆盖实际使用的自维护包及 VINS、EGO 等依赖，保留构建日志。下载缓存可复用，旧二进制不能冒充重建。
3. 提供可复制的构建、分层调试、完整启动、发送目标、查看状态、降落和停止命令；初始化失败会明确报告，停止后只清理本项目进程。
4. 独立保存真值调试和最终视觉组合；最终启用的配置必须是运行验证后的配置。

### B 单相机输入与 VINS 定位真实生效

1. 双目图像与相机 IMU 均来自同一个运动一致的 D435i 等效模型；用模型生成匹配内外参，核验深度单位、optical frame、时间戳和仿真时间。
2. 最终运行从 VINS 初始化开始不使用真值位置引导或 GPS 接管；静置不能初始化时实现明确的可复现无真值初始化流程，或阻止起飞并继续修复。
3. 用实际 ROS 订阅图、节点参数、PX4 参数／估计器状态及 ULog 证明：地图和 EGO 使用 VINS；EKF2 实际融合外部视觉；没有隐藏的 GPS／仿真位姿／DLIO 位置回退。仅发布 VehicleOdometry 不足以证明已融合。
4. 记录优化与传播输出的频率、延迟、位姿／速度 frame、重置和故障状态。不得靠重复旧消息、重写 stamp 或关闭健康门控维持表面正常。
5. 相对 Gazebo 真值给出实际 VIO 轨迹误差；允许一次 SE(3) 刚体对齐，不允许自由缩放或逐段重对齐掩盖漂移。

### C 在线建图可用于避障

1. 地图由在线深度与采样时刻位姿生成，不能把世界完整几何、真值点云或预制占据地图注入在线链路。
2. 实现 occupied／free／unknown、膨胀、有效范围、更新时间和深度失效门控。未知、无效深度、视野外区域不得无条件当作自由空间。
3. 建图随移动更新，提供障碍和墙面几何对照、地图延迟与重影分析；保存同一 epoch 的累计几何地图和带元数据的局部占据快照，并实际回读检查。
4. 快照与关键帧包含 frame、K／外参或其版本、源 stamp、epoch、map_id、配置哈希。回读展示通过不等于跨重启重定位，后者不在本目标内。

### D EGO 避障与任务闭环

1. 在最终视觉组合下，实际执行冷启动、初始化、解锁、起飞、EGO 避障、到达反馈和降落；由 PX4 状态确认着陆与解除解锁。
2. 实现三维位置与 yaw 目标、容差、到达停留、取消、替换、超时和失败原因。简单航点与 EGO 两种模式均可使用，控制出口始终唯一。
3. 正常场景至少包括空场、单障碍、错位多障碍和满足膨胀后通行条件的窄道，每场景 **3 次独立冷启动，全部成功且零碰撞**。另设不可达目标，明确拒绝或超时失败，不持续盲飞。
4. 至少一个避障场景的起终点直连被障碍阻断，实际轨迹绕开；测试组合覆盖至少一次高度变化和不同 yaw 目标，避免固定 1 米高度演示冒充三维目标支持。
5. 每次记录到达位置／yaw 误差、跟踪误差、最小机体间距、重规划时间、定位误差与任务结果；间距和碰撞用真值机体几何／接触记录评估，不能只看轨迹线。
6. 单前向相机的航向和观测范围约束实际生效；速度受视野、总延迟及实测制动能力约束，不通过盲区高速运动完成演示。

### E 故障与长时运行

1. 双目断流、相机 IMU 断流、深度断流、VINS 进程重启、规划器退出和仿真时钟回退，分别执行至少 **2 次独立故障注入**，记录触发、检测、行为和最终 PX4 状态。
2. 地图／轨迹失效时不无限执行旧轨迹；定位失效时不依赖旧坐标持续悬停。按已冻结的状态机退出自主任务，PX4 Offboard 丢失后按超时 Land，禁止自动重进。异常降落若因无有效定位发生漂移，必须量化并满足已冻结的故障边界，不能用“发出了 Land”代替结果。
3. epoch 改变或时间倒退后，旧地图、目标、轨迹失效；恢复为新会话，不假装续接旧地图。
4. 最终视觉组合至少完成一次 **连续 10 分钟** 的定位、地图、规划与控制完整负载运行，包含实际飞行任务／重规划，记录 CPU／内存／延迟曲线，无崩溃、无持续失控、无无界积压。

### F 定量标准先冻结再正式验收

1. 建立 `config/acceptance.json` 或等价单一验收配置，明确位置／yaw 到达容差与停留时间、定位误差、地图几何误差、跟踪误差、最小机体间距、最大数据年龄、重规划期限和故障检测／退出超时。
2. 正式验收前，依据 P1／P2 的独立校准实验及机体尺寸冻结这些数值、适用场景、测量方法和理由，保留配置哈希。冻结后再开始 D／E 的正式运行；不能看到最终结果后改阈值使其通过。
3. 正常任务的默认验收起点为：到达位置误差不超过 0.30 m、yaw 误差不超过 15°、持续满足至少 3 s。若证据表明需要变更，先记录工程理由与决定，再重新冻结并重跑受影响的正式测试；不能静默放宽。
4. 程序化检查冻结标准并生成 PASS／FAIL，失败与中断运行保留；最终报告必须列出全部正式 run，不只挑选成功片段。硬性范围、次数、单相机与无真值约束不得自行降低。

### G 后续算法能够接入

1. 提供有说明和样例的导航目标／取消／反馈、地图查询、RGB-D 关键帧、定位状态与 epoch 接口。
2. 用一个独立最小调用程序实际提交观察位姿、接收到达或失败结果、读取地图状态及至少一组带位姿的 RGB-D 关键帧，证明接口可用。该程序不发布 PX4 控制、不包含信念或探索算法。
3. 输入失效或跨 epoch 时拒绝使用；后续决策仍受相同碰撞与控制状态机约束。
