# GOAL C 空中机体包络采集前置门诊断 #384–#387

- **任务摘要**：继续 #383 的模型包络复核，尝试从空中起点取得新的同 epoch 样条与地图快照。
- **用户约束**：只推进单 D435i 仿真导航；保护既有工作区修改；truth 仅限隔离调试；PX4 控制只由 uav_px4_bridge 发布；不把失败探针或静态分析登记为通过。
- **决定**：依次运行第二障碍布局高膨胀 #384、默认膨胀短目标 #385、无附加障碍基线且带只读采集器 #386、相同基线但不启动采集器 #387。所有 run 使用 no-truth profile，保留现有定位与 PX4 稳定性门。
- **结果**：四轮均达到 VIO/map 初始前置条件，但 5 秒 PX4 遥测稳定与定位稳定未通过；PX4 vehicle_status 中 pre_flight_checks_pass 为 0/N。没有调用 EnableOffboard、没有派发目标、没有输出 PX4 控制样本，车辆保持 disarmed。#384–#386 的样条/快照观察器均超时且没有收到样条。
- **对照**：四轮时钟区间 RTF 为 0.291–0.302，estimator_flags 与 land_detected 接收间隔中位数约 3.30–3.42 秒；历史 #200 对照分别约 0.641 与 1.53 秒。四个变量组合没有改变本轮前置门结果；历史 #200 未记录不可变容器摘要，不能据此归因根因。PX4 日志中的 ekf2 missing data 与 system power unavailable 警告在 #200 也出现过，不能单独解释本轮差异。
- **待决问题**：当前仿真吞吐／PX4 状态遥测为何较历史基线退化仍未定位。下一步先恢复并测量稳定的 PX4 telemetry 与时钟速率，再尝试空中样条／快照和完整包络扫掠。
- **证据**：[汇总报告](../../progress/evidence/p5-vio-ego-airborne-preflight-diagnostic-20261021-384-387.json)；运行目录分别为 #384、#385、#386、#387，均包含 SHA-256 清单。
